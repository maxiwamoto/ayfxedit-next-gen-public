# AYFXEDIT NEXT GEN game audio SDK

Generated by AYFXEDIT NEXT GEN, Max Iwamoto. The editor is based on Shiru's AY Sound FX Editor and Threetwosevensixseven's improved fork. These players implement the NEXT GEN compact channel format. Classic AFX import/export remains available in the editor.

## Build locally

- Primary assembler: tniASM using its bundled `compat.asm`. Set `TNIASM` to the executable, then run `build_tniasm.bat`. The default is `tniasm.exe` on PATH.
- C: SDCC Z80, tested with 4.6.4. Set `SDCC` to the executable, then run `build_sdcc.bat`. It compiles and links both targets without a CRT.
- The `.bin`/`.ihx` examples are callable integration modules at 8000h, **not bootable ROMs**. RAM state starts at C000h (37 bytes on Z80). Include the sources in your game and choose your own code/RAM locations. Avoid overlap with your stack, bank window, music player or firmware.
- The ASM instructions use tniASM conventions. SDCC emits its own assembler dialect; its generated `.asm` files are compiler outputs. No other hand-written assembler dialect is claimed compatible.

## Assembly integration

Include `record_layout.asm`, `player.asm`, `mixer.asm`, one `io_*.asm` and `effects.asm`. Define `AYFX_STATE` to a contiguous 37-byte RAM region. The player itself can reside in ROM: it deliberately keeps state in a record instead of modifying instructions.

1. Call `AYFX_INIT` once. This captures PSG R7 I/O-direction bits.
2. Load HL with the pointer from `AYFX_BANK + effect_id * 2` and call `AYFX_START`. Carry means a lower-priority effect was rejected; equal priority replaces the current effect.
3. At the bank-report tick rate (50 or 60 Hz), call `AYFX_TICK`, load HL with your music player's 14-register shadow (or 0000h for silence), call `AYFX_MIX`, then `AYFX_WRITE`.
4. Call `AYFX_STOP` when needed; call MIX/WRITE afterwards to restore music or silence.

AF/BC/DE/HL are clobbered. IX/IY are preserved. Helpers never execute DI/EI, HALT or BIOS calls. Call from the game's serialized audio service. Starting/stopping effects must not race the frame service. If PSG is also used by mouse/joystick code, serialize complete register-select/data transactions with that owner. No R14/R15 data writes occur. If your game changes R7 I/O direction after INIT, update AYFX_GPIO (upper two bits) accordingly.

## Small games without a separate music player

Use `standalone_layout.asm`, `player.asm`, one `io_*.asm` and `effects.asm`; omit `mixer.asm`. This variant uses **23 bytes of RAM**. Call INIT/START/STOP as above, and TICK then WRITE each audio tick. `example_small_msx.asm` and `example_small_spectrum.asm` demonstrate it and are built by `build_tniasm.bat`. It retains 1/2/3-channel effects, priority, loops, noise and envelopes. It owns all three AY channels; do not use it alongside an independent music writer. For sharing channels with music, use the 37-byte state and optional mixer described above.

## SDCC integration

`example.c` demonstrates `game_audio_init`, `game_sound(id)` and `game_audio_frame(music)` with a persistent AyfxPlayer. Compile ayfx_player.c with `-DAYFX_MSX=1` for MSX, without it for Spectrum. Functions use SDCC's current Z80 C calling convention; call through the C header rather than assuming a hand-written register ABI. The C player performs the same operation as the smaller assembly player, but has greater CPU cost.

## Music and shared resources

One group of 1/2/3 channels plays at once. Its priority is 0-255 (higher wins). Its assigned tone/volume/mixer bits override music, while unused channels retain music. Noise and envelope are each shared by the chip. When an effect uses noise, other music noise inputs are muted for that effect's duration. When it uses the envelope, other envelope-driven music channels are muted. The music engine should continue advancing its shadow registers while SFX plays. R13=FFh means **do not retrigger**. Music envelope phase cannot be restored after an SFX takes that generator; the music player may need to retrigger at a musical boundary.

MSX ports are A0h/A1h/A2h. Spectrum ports are FFFDh/BFFDh (128/+2/+3 or compatible AY expansion; unexpanded 48K has no AY). Match the bank-report clock and tick rate. Examples do not install an interrupt or resample 50 Hz data to 60 Hz. The bank, code and RAM record must remain mapped across calls. Relocate or split banks to fit your actual mapped window; there is no implicit cartridge mapper support.

## Compact data format, version 2

`effects.asm` uses absolute pointers in AYFX_BANK. `effects.bin` and the C array in `effects.h` use little-endian offsets from bank start. Do not interpret those offsets as absolute pointers. Identical effects share one entry, including header, priority and loop settings. Named IDs remain separate. The bank contains no source audio, names, per-frame timestamps or repeated loop expansions.

Each effect has a **4-byte header**: channel/resource mask, priority, and a 16-bit loop offset from the effect start (FFFFh = no loop). Mask bits 0..2 are A/B/C, bit 3 reserves noise and bit 4 reserves the hardware envelope. Clock and tick rate are bank-level settings in bank-report.txt.

Stream records:

- 00h: end, or jump to the loop.
- 80h..FFh: hold the current sound for 1..128 ticks (`(command & 7Fh) + 1`). Envelope shape is not retriggered during a hold.
- 01h..7Fh: one channel update frame. Bits 0..2 select A/B/C; bit 3 adds noise period; bit 4 adds the 16-bit envelope period; bit 5 adds an explicit shape trigger; bit 6 adds mixer bits. Payloads follow this order.
- Each selected channel starts with one descriptor: bits 0..4 = volume (including envelope enable); bit 5 adds the low tone byte; bit 6 adds the high tone byte. Only changed tone bytes follow. Bit 7 is reserved.

First frames and loop targets restore the tone, volume, mixer, noise and envelope period state. Shape triggers are emitted only for explicit events, including consecutive writes of the same shape. Players accept trusted build artifacts; they do not bounds-check corrupt streams. Keep this bank and runtime version together; the previous experimental format is incompatible.

`bank-report.txt` lists per-effect bytes and deduplication savings. A long sustained effect can be very small, while rapidly changing three-channel data takes more space. Export only the effects your game needs. Data must fit the game's mapped address window; the 64 KB format limit does not supply a cartridge mapper.

## VGM conversion

Tools > Extract PSG / VGM capture still imports a single AY chip into editable tracks. Export game SDK then uses this compact format, retaining all selected channels, shared noise, envelope period and retrigger events. Existing import limits apply: uncompressed single-AY VGM, 50/60 Hz quantization, and up to 4096 frames per selected effect. This is effect extraction, not a cycle-exact general VGM music player.

## Verification

Compiled tniASM and SDCC players are checked on a Z80 emulator for both MSX and Spectrum. The tests include imported three-channel VGM with shared noise, envelope period changes and consecutive identical retriggers, loops, holds, bank deduplication, music sharing, GPIO preservation and interrupt neutrality. The 23-byte standalone variant is checked separately.

The Castlevania cartridge test compares every output frame against an independent AFB decoder in the custom openMSX fork. Timing results and exact code/data sizes are recorded in the repository's tests/msx/README.md. Measurements describe those test cases, not a universal CPU budget; Spectrum hardware contention is not simulated by the unit-test CPU emulator.

Hardware references: [MSX I/O map](https://map.grauw.nl/resources/msx_io_ports.php), [Spectrum ports](https://www.worldofspectrum.net/faq/reference/ports.htm).
